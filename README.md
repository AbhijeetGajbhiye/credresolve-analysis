# CredResolve Collections Analytics — Is the 11% Real?

Data Analyst assignment, Round 1. Full writeup in `notebook/analysis.ipynb`
and `reports/executive_memo.docx`. This README is the map.

## Headline finding

The reported "recovery improved 11% month-on-month" is a calendar-day
artifact: February has 3 fewer days than March, and the raw month-over-month
comparison used to report the figure was never normalized for that. Recovery
per day is flat (Rs 5.8-6.1M/day, no trend) across the entire Jan-Jul 2026
window. The one real, actionable finding is a coverage gap: 22.2% of the
loan book (6,656 of 30,000 accounts, Rs 231 Cr outstanding) has never been
assigned to any collection activity, despite being statistically identical
to the worked book.

## How to reproduce

```bash
# Option A: Python pipeline (writes golden_dataset/golden_*.csv + a DQ log)
cd pipeline && python3 build_golden_dataset.py

# Option B: SQL pipeline (also writes credresolve.db + all metric/driver CSVs)
python3 pipeline/run_sql_pipeline.py

# Notebook (already executed and saved with output; to re-run from scratch)
cd notebook && jupyter nbconvert --to notebook --execute --inplace analysis.ipynb
```

Both pipelines were built independently (Python and SQL) and cross-checked
against each other on every headline number; they agree to within rounding.

## The four assignment questions, answered

1. **What happened?** Performance was flat Jan-Jul 2026. No properly-normalized
   metric shows a sustained trend. See notebook Sections 4-5.
2. **Why?** Almost nothing tested (portfolio mix, DPD, channel, vendor, calling
   hour, attempt number, agent tenure) explains variation, because there is
   none to explain. The one real driver found is the coverage gap. See
   notebook Section 6 for the Fact/Strong-Evidence/Correlation/Hypothesis table.
3. **Is the 11% real?** No. See notebook Section 4 and the Data Quality Report.
4. **Where to invest Rs 10 Cr?** AI voice automation, targeted at the untouched
   22% of the portfolio, validated with a controlled pilot first. Full ROI
   model in the Executive Memo and notebook Section 8.

## Key data-quality findings (full detail in `reports/data_quality_report.md`)

- Payments: 500/25,500 rows (1.96%) were duplicate ingestion events
- Agents: 1,000 real agents behind 30,000 raw dimension rows, with
  employee_code/vendor/team randomized per snapshot; agent_id is the only
  reliable key
- Borrowers: same pattern, 11,015 real borrowers behind 30,600 raw rows
- Call dispositions: `PTP` and `PROMISE_TO_PAY` are the same outcome recorded
  under two different strings, across every disposition version
- Timezones: calls/accounts/sessions mix UTC, Asia/Kolkata, and Asia/Dubai
  with no normalization in the raw feed
